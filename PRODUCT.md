# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

.NET developers building ASP.NET Core apps (Minimal APIs, MVC, FastEndpoints) who want React, Vue or Svelte frontends without a separate API layer, and who read the docs to install, wire up and ship an Inertia v3 app. AI coding agents are a first-class second audience: they consume `llms.txt`, `llms-full.txt` and the agent guide to write integration code.

## Product Purpose

Inertia.Net is a .NET 10 server adapter for the Inertia.js v3 protocol. Endpoints pick a frontend page and supply its props; the client renders it with no hand-written API. The docs site (`docs/Inertia.Net.Docs`) teaches installation, props, partial/deferred/merged/once props, validation, SSR, Vite, AOT, testing and migration. Success is a developer getting a working app and finding answers quickly, whether they or their agent is reading.

## Positioning

- Full Inertia v3 protocol across three hosts (Minimal APIs, MVC, FastEndpoints), verified by one shared conformance suite.
- Native AOT support for Minimal API apps, with source-generated System.Text.Json metadata.
- The docs site is itself an Inertia.Net app (React 19, SSR via Bun), so it dogfoods the product.

## Operating Context

Readers work in an editor and terminal beside the docs, copying C# and client snippets, switching between React/Vue/Svelte. Content is MDX in `docs/Inertia.Net.Docs/content/docs`; navigation, search index and agent files are generated by `scripts/generate-docs.mjs`. Sections: Get started, Essentials, Loading data, Production, Reference, Tutorial.

## Capabilities and Constraints

- Docs stack: ASP.NET Core Minimal API, React 19, Inertia v3 client, Tailwind CSS, MDX, Bun for install/build/SSR.
- Generated artifacts (nav manifest, search index, `llms*.txt`) are committed; content changes must regenerate them.
- Repository rules in `AGENTS.md` apply: no assistant attribution; small changes; keep Native AOT intact.
- Samples live in a separate repository (Inertia.Net-Samples); this repo has only templates and the docs site.

## Brand Commitments

Name: Inertia.Net. The existing docs look is not binding; the user is open to a rebrand. Voice is plain, technical, and honest about limits and deliberate protocol deviations.

## Evidence on Hand

- Published benchmark rounds against prior NuGet releases in `README.md`.
- Live sample demos (Inkwell, TechLandier, CarParker) hosted outside this repo.
- Absent: customer testimonials, logos, adoption numbers. Do not fabricate them.

## Product Principles

1. Answer fast: a developer should find the exact snippet or reference without hunting.
2. Code is the primary content; prose supports it.
3. Serve humans and agents equally; machine-readable output is a feature, not an afterthought.
4. Be candid about deviations, limits and what is unsupported (for example MVC and Native AOT).
5. Dogfood: the docs site should demonstrate the adapter's own capabilities.

## Accessibility & Inclusion

No product-specific standard was stated; default to WCAG 2.1 AA, keyboard-navigable docs and code blocks, and sufficient contrast in light and dark themes.
