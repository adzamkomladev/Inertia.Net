You can publish an Inertia.Net app with Native AOT. `Inertia.Net`, `Inertia.Net.FastEndpoints` and `Inertia.Net.Live.SignalR` are annotated `IsAotCompatible`. CI publishes a real app with Native AOT (`tests/Inertia.Net.AotSmoke`) with zero trim and AOT warnings allowed. The library never reflects over your props. It writes values with `JsonTypeInfo` from your `JsonSerializerContext`.

## 1. Register a JSON context

Register every prop type and chain the context into the HTTP JSON options:

```csharp
builder.Services.ConfigureHttpJsonOptions(o =>
    o.SerializerOptions.TypeInfoResolverChain.Insert(0, AppJsonContext.Default));

[JsonSerializable(typeof(UsersPage))]               // typed page props
[JsonSerializable(typeof(Page<UserDto>))]           // closed pagination types you return
[JsonSerializable(typeof(UserDto))]
[JsonSerializable(typeof(List<UserDto>))]           // closed collection types you return
[JsonSerializable(typeof(UserDto[]))]
[JsonSerializable(typeof(Stats))]                   // the T of Defer(() => new Stats(...)) and friends
internal sealed partial class AppJsonContext : JsonSerializerContext;
```

Register these in the context:

- the type that each loader returns
- each plain value you place in `InertiaProps`
- flash values that are not plain strings or numbers

The library's own context already covers `string`, `bool`, `int`, `long`, `double`, `decimal`, `float`, `Guid`, `DateTime`, `DateTimeOffset`, `DateOnly`, `TimeOnly`, `TimeSpan`, `JsonElement`, `string[]`, `int[]`, `List<string>`, `Dictionary<string, string>`, `Dictionary<string, string[]>`, `InertiaProps` and `Dictionary<string, object>`.

The source generator accepts members of type `InertiaProp` without any attribute.

## 2. Make validation models public

The .NET 10 `AddValidation()` source generator skips internal types. Validation of those types then does nothing and reports no error. Only one `AddValidation()` call site per project is allowed.

## 3. Add ProblemDetails

```csharp
builder.Services.AddProblemDetails();
```

The non-Inertia `400` validation problem needs the `ProblemDetails` JSON metadata, or it cannot be serialized without reflection.

## 4. Avoid anonymous types

Anonymous types do not work as props, flash values or published [live prop](/docs/live-props) values under AOT. Use `InertiaProps`, records or classes registered in the context. Register the types you publish as live values in the same context.

## 5. Copy content files

The app reads `app.html` and the Vite manifest from disk at runtime. Copy them to the publish directory. When the binary may run from another directory, set the content root to the binary's directory:

```csharp
var builder = WebApplication.CreateSlimBuilder(new WebApplicationOptions
{
    Args = args,
    ContentRootPath = AppContext.BaseDirectory,
});
```

In the project file:

```xml
<PropertyGroup>
  <PublishAot>true</PublishAot>
  <JsonSerializerIsReflectionEnabledByDefault>false</JsonSerializerIsReflectionEnabledByDefault>
</PropertyGroup>
<ItemGroup>
  <Content Include="app.html" CopyToPublishDirectory="PreserveNewest" />
</ItemGroup>
```

## 6. Use Minimal APIs or FastEndpoints

`Inertia.Net.Mvc` is not AOT compatible, because ASP.NET Core MVC itself is not. Use Minimal APIs or FastEndpoints.

## 7. FastEndpoints source generation

```csharp
builder.Services.AddFastEndpoints(new[] { DiscoveredTypes.All });
```

`DiscoveredTypes` is generated by the `FastEndpoints.Generator` package, in the namespace named after the assembly. See `samples/FastEndpoints.Svelte`.

## 8. Trim HTTP/3

The SSR client never uses HTTP/3, so HTTP/3 support can be trimmed out:

```xml
<ItemGroup>
  <RuntimeHostConfigurationOption Include="System.Net.SocketsHttpHandler.Http3Support" Value="false" Trim="true" />
</ItemGroup>
```

These features are all AOT safe and covered by the smoke test:

- cached props
- the SSR cache
- nonces
- prefetching
- `MapInertia`
- the DevTools recorder
- [live props over SignalR](/docs/live-props#signalr)

SignalR itself does not support strongly typed hubs (`Hub<T>`) under AOT, so keep any hubs of your own untyped.

<Callout type="tip" title="Catch missing registrations early">
Set `JsonSerializerIsReflectionEnabledByDefault=false` in regular builds too. A missing `JsonSerializable` registration then fails in tests instead of only in the AOT publish.
</Callout>

The reference app is `tests/Inertia.Net.AotSmoke/Program.cs`. Run it end to end with `bash eng/aot-smoke.sh` on Linux with clang and zlib installed.
