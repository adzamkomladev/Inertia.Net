A live prop refreshes itself when the server broadcasts an event. The page response says which props listen to which events; the client subscribes to those channels and, when an event arrives, reloads the affected props or applies the values the event carries. Components never subscribe or clean up.

Three pieces make it work:

1. **An event**, defined once as a `LiveEvent` and shared by both sides.
2. **A prop marked `.Live(event)`**, which puts its listeners in the page's `liveProps`.
3. **A publish** through `IInertiaLive`, delivered to subscribers by a transport.

<Callout type="info" title="Client version">
Live props need `@inertiajs/react`, `@inertiajs/vue3` or `@inertiajs/svelte` 3.11.0 or later. Older clients ignore `liveProps`.
</Callout>

## Define each event once

A `LiveEvent` is an event name on a `LiveChannel`. The same value declares the prop and publishes the event, so the two sides cannot drift apart.

```csharp
public static class OrderEvents
{
    public static LiveEvent Updated(int id) => new("OrderUpdated", LiveChannel.Private($"orders.{id}"));
    public static LiveEvent StatsChanged { get; } = new("StatsChanged", LiveChannel.Public("stats"));
}
```

Channels are `LiveChannel.Public`, `Private`, `Presence` or `EncryptedPrivate`. Names carry no prefix; a transport adds `private-` or `presence-` itself when its protocol needs one.

## Mark props live

```csharp
app.MapGet("/orders/{id:int}", (int id, AppDb db) => Render("Orders/Show", new InertiaProps
{
    ["order"]   = Prop(ct => db.Orders.SingleAsync(o => o.Id == id, ct))
                      .Live(OrderEvents.Updated(id))
                      .Throttle(TimeSpan.FromMilliseconds(500)),
    ["metrics"] = Defer(ct => metrics.ForOrderAsync(id, ct)).Live(OrderEvents.Updated(id)),
    ["stats"]   = Optional(() => stats.Today()).Live(OrderEvents.StatsChanged),
}));
```

The page lists every listener, including those of props it left out:

```json
{
  "props": { "errors": {}, "order": { "id": 1, "status": "paid" } },
  "deferredProps": { "default": ["metrics"] },
  "liveProps": {
    "order": {
      "listeners": [
        { "channel": { "name": "orders.1", "type": "private" }, "events": ["OrderUpdated"] }
      ],
      "throttle": 500
    },
    "metrics": {
      "listeners": [
        { "channel": { "name": "orders.1", "type": "private" }, "events": ["OrderUpdated"] }
      ]
    },
    "stats": {
      "listeners": [
        { "channel": { "name": "stats", "type": "public" }, "events": ["StatsChanged"] }
      ]
    }
  }
}
```

| Call | Effect |
|---|---|
| `.Live(event)` | Adds a listener. Repeatable: call it once per event. |
| `.Live(channel, "Created", "Deleted")` | Listens to several events on one channel. |
| `Live(() => ..., event)` | The factory form of `Prop(...).Live(event)`. |
| `.Throttle(window)` | The shortest time between two reloads of the prop. The client's default is one second. |

### What combines with live

| Prop | Live? | Notes |
|---|---|---|
| `Prop`, `Always`, shared props | Yes | |
| `Defer`, `Optional` | Yes | Listeners are reported even while the value is left out. |
| `Once` | Yes | A once prop the client already holds stays subscribed. |
| `Rescue`, `Parallel` | Yes | A rescued prop stays subscribed; the next event fetches it again. |
| `Cache` | Yes | Publishing does not evict the cache. Remove the entry with `IInertiaCache` first. |
| `Merge`, `DeepMerge`, `Scroll` | No | A live prop is replaced whole, so these throw `InvalidOperationException`. |

A live prop inside an array reloads its whole array, as every [partial reload](/docs/partial-reloads) of an array descendant does. Prefer keyed objects for lists that change often.

## Shared live props

A shared live prop keeps something current on every page, such as a notification bell:

```csharp
builder.Services.AddInertia(o => o.Share("notifications", ctx =>
{
    var userId = ctx.User.FindFirstValue(ClaimTypes.NameIdentifier);
    return userId is null ? null : Prop(ct => notifications.SummaryAsync(userId, ct))
        .Live(new LiveEvent("NotificationCreated", LiveChannel.Private($"users.{userId}")));
}));
```

## Publish events

`AddInertiaLive()` registers `IInertiaLive`. A transport registers the `IInertiaLiveBroadcaster` that delivers what it publishes.

```csharp
builder.Services.AddInertiaLive();   // then a transport: .AddSignalR() or your own IInertiaLiveBroadcaster
```

<Tabs>
<Tab label="Reload">

```csharp
// Everyone else on the channel reloads `order`; the caller already has the response.
app.MapPost("/orders/{id:int}/ship", async (int id, HttpContext context, IInertiaLive live) =>
{
    await orders.ShipAsync(id);
    await live.PublishAsync(OrderEvents.Updated(id), exceptSocketId: context.InertiaRequest().SocketId);
    return Back();
});
```

</Tab>
<Tab label="With values">

```csharp
// Clients apply the value without a request; live props left out are reloaded.
await live.PublishAsync(OrderEvents.Updated(order.Id), new { order = OrderDto.From(order) });
```

</Tab>
<Tab label="Explicit metadata">

```csharp
// Written with that context's own options, as JsonSerializer would.
await live.PublishAsync(OrderEvents.Updated(order.Id), new OrderProps(dto), AppJsonContext.Default.OrderProps);
```

</Tab>
</Tabs>

- **Without values**, every client reloads the live props that listen to the event, each with its own request and its own data.
- **With values**, keyed by prop path (`"auth.user"` stays a flat key), those props are updated in place. Values use the page serializer options, so they match what a reload returns; under Native AOT the type needs to be in your registered JSON context, like any prop type.
- **`exceptSocketId`** leaves one connection out, usually the client that made the change. The client sends its id as `X-Socket-Id` and `HttpContext.InertiaRequest().SocketId` reads it. The header is client-supplied, so it is only ever used to exclude.

<Callout type="danger" title="Every subscriber sees the same values">
A broadcast reaches every client on the channel. Only publish values that everyone allowed on the channel may see. When a value depends on the user, publish without values and let each client reload its own.
</Callout>

What a broadcaster delivers:

```json
{
  "__inertia": {
    "event": "OrderUpdated",
    "props": { "order": { "id": 1, "status": "shipped" } }
  }
}
```

## On the client

Read a live prop like any other prop. `useProp` exposes its loading state, and the cancelable `live` router event can hold an update back, for example to show a "new posts" button instead:

```tsx
import { router, useProp } from '@inertiajs/react'

const order = useProp<Order>('order')   // { value, loading, loaded }

router.on('live', (event) => {
  if (event.detail.props.includes('posts')) {
    showNewPostsButton()
    return false
  }
})
```

## SignalR

`Inertia.Net.Live.SignalR` runs the transport inside your app: a SignalR hub the browser subscribes to, channel authorization, and the broadcaster that `IInertiaLive` publishes through.

```sh
dotnet add package Inertia.Net.Live.SignalR
npm install @microsoft/signalr
```

```csharp
builder.Services.AddInertiaLive().AddSignalR(o =>
    o.Authorize((context, channel, ct) =>
        ValueTask.FromResult(channel.Name == $"users.{context.UserIdentifier}")));

var app = builder.Build();
app.UseAuthentication();
app.UseAuthorization();
app.UseInertia();
app.MapInertiaLiveHub();   // /inertia-live
```

Apps created with `dotnet new inertia` ship the client transport as `ClientApp/lib/inertia-signalr.ts`. In other apps, copy [the file](https://github.com/adzamkomladev/Inertia.Net/blob/main/src/Inertia.Net.Templates/content/common/ClientApp/lib/inertia-signalr.ts) in, then turn it on:

```ts
import { signalr } from './lib/inertia-signalr'

createInertiaApp({ live: signalr() })
```

`@microsoft/signalr` loads on the first subscription, so pages without live props never download it. When a dropped connection comes back, the transport joins its channels again and Inertia reloads every live prop once, catching up on missed events.

### Who may join a channel

| Channel | Who joins |
|---|---|
| `Public` | Anyone who reaches the hub. Set `o.AuthorizePublicChannels = true` to ask the authorizer too. |
| `Private`, `Presence`, `EncryptedPrivate` | Only connections the authorizer allows. With no authorizer, nobody. |

For rules that need services, implement `ILiveChannelAuthorizer` and register it with `o.Authorize<OrderChannelAuthorizer>()`. It is created for each subscription, with constructor injection. SignalR has no presence member lists or end-to-end encryption, so presence and encrypted-private channels are authorized like private ones.

The hub answers requests from other origins with 403 (add trusted ones to `o.AllowedOrigins`). That check stands in for antiforgery tokens on the hub. Connections close when their authentication expires.

<Callout type="warning" title="More than one server">
SignalR groups live on one server. Behind several instances, add a Redis backplane (`AddSignalR().AddStackExchangeRedis(...)`) or Azure SignalR Service; without one, a publish reaches only the clients connected to the instance that sent it.
</Callout>

The [package README](https://github.com/adzamkomladev/Inertia.Net/blob/main/src/Inertia.Net.Live.SignalR/README.md) lists the client options, how channels map to SignalR groups, and the security notes.

## Custom transports

The page metadata and the payload do not depend on SignalR, so any transport works:

- **Pusher-protocol servers** (Reverb, Soketi, Ably, Pusher) work with the client's built-in `pusher()` or `echo()` transport. On the server, implement `IInertiaLiveBroadcaster` with your server's publish API.
- **Anything else** (Action Cable, server-sent events, Azure Web PubSub): implement `IInertiaLiveBroadcaster` on the server and a `LiveTransport` on the client.

A broadcaster has one method. It receives the channel, the finished payload and the connection to skip:

```csharp
public sealed class MyBroadcaster : IInertiaLiveBroadcaster
{
    public ValueTask PublishAsync(LiveMessage message, CancellationToken cancellationToken = default)
    {
        // message.Channel.Key:      "private:orders.1"
        // message.Payload:          {"__inertia":{"event":"OrderUpdated",...}}, a JsonElement
        // message.ExceptSocketId:   the connection to leave out, or null
        throw new NotImplementedException("Send message.Payload to the channel's subscribers.");
    }
}
```

## Testing

`InertiaPage.LiveProps` holds the metadata, and `HasLive` asserts it, with the channel written as `"{type}:{name}"`:

```csharp
await response.AssertInertiaAsync(page => page
    .HasLive("order")
    .HasLive("order", "private:orders.1", "OrderUpdated"));
```
