Inertia DevTools lets you see what your browser sent and what ASP.NET Core returned for an Inertia visit.

## Try it in the starter

DevTools lets you inspect a visit without changing its response. Its read API, the endpoints that return the recorded entries,
leaves pending errors and flash messages alone. Apps hosted under a path such as `/admin` report that path to the extension.
Request URLs are absolute. Recorded URLs redact sensitive query values and omit parameterized or percent-encoded fragments.
Plain anchors such as `#overview` are kept.

Entries live in memory and disappear on restart. Source-call locations are not collected, so some “open in editor” links
are unavailable. Keep the read API private, because recorded entries can include user data.

1. Install the browser extension using the [Inertia.js DevTools guide](https://inertiajs.com/docs/v3/advanced/devtools#installation).
2. Start the app and Vite from [First 10 minutes](/docs/first-10-minutes). Open `http://localhost:5180/todos`, open your browser's developer tools, and select the **Inertia** panel.
3. Submit an empty todo title. Select the visit in the timeline and look at the request and the resulting page data. The validation message is under `props.errors.title`.

The starter enables recording in Development. To add recording to an existing app, use the setup below.

## Enable DevTools

```csharp
builder.Services.AddInertiaDevTools();   // records in Development only
app.UseInertia();
app.MapInertiaDevTools();                // GET /_inertia/devtools/entries/{id} and /entries
```

The list endpoint returns metadata summaries. Fetch `/entries/{id}` for props, HTTP bodies and route details.
The recorder captures plain text and JSON responses up to `MaxResponseBytes`. It omits ordinary HTML and XML bodies,
binary data, explicitly streamed responses and oversized bodies. Inertia page entries keep their redacted page data. Parsed multipart forms include file names, sizes and MIME types, never file contents.
Unparsed uploads are not read only for recording. Render source locations are included when debug symbols are available.
Published or Native AOT applications may not retain them. Malformed structured bodies and invalid UTF-8 are omitted, because
a raw-text fallback could expose an unredacted secret.

To exclude paths, use `o.ExcludePaths.Add("/health")` or `o.ExcludePaths.Add("/assets/*")` in `AddInertiaDevTools(o => ...)`.
Untagged requests use the global entry/byte/age limits. `MaxEntriesPerTab` applies only when a browser tab ID is supplied.

Each request through `UseInertia()` gets an `X-Inertia-Devtools-Id` and an entry in memory. Entries are kept per browser tab, at most `MaxEntriesPerTab` and `MaxEntries`, for `MaxAge`. An entry holds:

- request type
- timings
- headers
- bodies
- the page object and its props metadata, including `durationMs`: how long each prop's loader (or its cache lookup) took. A `Parallel()` loader is timed from when it got a slot.

The first page carries the discovery tag that the extension reads. In props, bodies and headers, DevTools replaces a value with `[REDACTED]` when its name contains `password`, `secret`, `token`, `authorization`, `cookie` or `api_key`. Add names with `RedactedKeys`. Nothing leaves the app.

Sensitive query parameters are also redacted in recorded request/page URLs, redirects and URL headers. Actual application URLs are unchanged. Malformed JSON bodies are omitted. Only eligible Inertia text bodies with a known length up to `MaxBodyBytes` are buffered. Unknown-length nonseekable bodies are omitted as streamed, so recording does not spool bulk requests to disk. A page larger than `MaxResponseBytes` is recorded without its body and is never copied. The default for `MaxResponseBytes` is 1 MiB. The entry is marked `too-large`, with the page size in `__meta.responseBytes`. The browser still receives the whole page. Kept entries are also bounded by `MaxTotalBytes`. The default for `MaxTotalBytes` is 64 MiB, and the oldest entries are dropped first.

Outside Development, nothing is recorded unless `Enabled = true`. Outside Development, the read API answers only requests that `Authorize` accepts. Other requests get `404`. With `Pages.Directory` set, entries link the component to its file.

## Page component check

To turn on the check, set `Pages.Directory`:

```csharp
builder.Services.AddInertia(o =>
{
    o.Pages.Directory = "ClientApp/pages";   // Development only
    o.Pages.Extensions = [".tsx", ".vue"];   // optional
});
```

In Development, `Render` throws when the component has no page file. The message names the closest one:

```text
'Users/Indx' was not found in 'ClientApp/pages' ... Did you mean 'Users/Index'?
```

Names match exactly, as the client resolver does, even on case-insensitive file systems. Outside Development there is no check and no file access.

`Pages.Extensions` lists the file types. The default is `.tsx`, `.jsx`, `.ts`, `.js`, `.vue` and `.svelte`.

## Generated TypeScript

The development startup also writes TypeScript declarations when `o.TypeScript.OutputPath` is set. The startup writes the file only when the content changed. See [TypeScript types](/docs/typescript).

## What to check before deploying

- `Pages.Directory` can stay configured. It is inactive outside Development.
- DevTools recording is off unless explicitly enabled.
- The generated TypeScript file is committed if the client build type-checks in CI.
- Production logs do not contain the DevTools read API.

Without an `Authorize` callback, the read API responds only in Development. Requests must come from this machine through a loopback connection to a loopback host name such as `localhost`. They must have no `X-Forwarded-For`, `Forwarded`, `X-Forwarded-Host`, `X-Real-IP` or `Via` header. Set `Authorize` to allow access from a container or another machine.

A reverse proxy on the same machine makes remote requests look local if it adds none of those headers. Set `Authorize` in that case too.

If recording is enabled outside Development without an `Authorize` callback, the app logs a warning and the read API returns 404. Map the read API with `MapInertiaDevTools()` and authorize its users.

The recorder's process-wide latch stays active after first use. The process-wide latch for parallel-prop planning does too.
