Inertia.Net uses the Inertia.js v3 protocol. Install a v3 client package. Inertia.Net does not support v2 clients.

## Install the client

Run the client setup commands from the ASP.NET Core project directory, the one that contains your `.csproj`. You can use npm, Bun,
pnpm or Yarn. The framework snippets below use npm commands. For another package manager, replace each command with its equivalent:

| Package manager | Add packages | Add development packages |
|---|---|---|
| npm | `npm install <packages>` | `npm install -D <packages>` |
| Bun | `bun add <packages>` | `bun add -D <packages>` |
| pnpm | `pnpm add <packages>` | `pnpm add -D <packages>` |
| Yarn | `yarn add <packages>` | `yarn add -D <packages>` |

Replace `<packages>` with the names and version ranges from your framework's snippet. If the project has no `package.json`,
create one first with `npm init -y`, `bun init -y`, `pnpm init` or `yarn init`.

`@types/node` provides the types for the `node:fs` import and for `process` in the Vite config. Add `vite/client` to `tsconfig.json` so that `import.meta.glob` is typed:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "noEmit": true,
    "skipLibCheck": true,
    "types": ["vite/client", "node"]
  },
  "include": ["resources/js", "vite.config.ts"]
}
```

For Vue and Svelte, use `"jsx": "preserve"` or omit that setting.

The starter templates use `ClientApp/pages`. The manual examples below use `resources/js/Pages`. Keep the resolver, file paths and Vite entry consistent with the layout you choose.

The templates also ship `ClientApp/lib/inertia-signalr.ts`, the client transport for [live props over SignalR](/docs/live-props#signalr). To turn the transport on, uncomment `live: signalr()` in `ClientApp/app.tsx` (or `app.ts`).

## Vite configuration

The Vite config is the same for every client, except for the framework plugin and the entry file. The entry file is `app.tsx` for React and `app.ts` for Vue and Svelte.

<Tabs>
  <Tab label="React">

```ts
// vite.config.ts
import { defineConfig, type Plugin } from 'vite'
import react from '@vitejs/plugin-react'
import { mkdirSync, rmSync, writeFileSync } from 'node:fs'

// Writes the dev server URL to wwwroot/hot. Inertia.Net reads it in Development
// and renders the dev-server tags instead of the manifest tags.
function hotFile(): Plugin {
  const file = 'wwwroot/hot'
  return {
    name: 'inertia-net-hot-file',
    apply: 'serve',
    configureServer(server) {
      server.httpServer?.once('listening', () => {
        const address = server.httpServer!.address()
        if (address && typeof address === 'object') {
          mkdirSync('wwwroot', { recursive: true })
          writeFileSync(file, `http://localhost:${address.port}`)
        }
      })
      const clean = () => rmSync(file, { force: true })
      process.on('exit', clean)
      process.on('SIGINT', () => process.exit())
      process.on('SIGTERM', () => process.exit())
    },
  }
}

export default defineConfig(({ command }) => ({
  plugins: [react(), hotFile()],
  // Built assets live at /build/. The dev server serves from the root because
  // Inertia.Net emits {origin}/@vite/client and {origin}/{entry}.
  base: command === 'build' ? '/build/' : '/',
  server: { port: 5173, strictPort: true, origin: 'http://localhost:5173' },
  build: {
    outDir: 'wwwroot/build',
    emptyOutDir: true,
    manifest: true,
    rollupOptions: { input: 'resources/js/app.tsx' },
  },
}))
```

Add these fields to `package.json`:

```json
{ "type": "module", "scripts": { "dev": "vite", "build": "vite build" } }
```

Pass the manifest key of the entry to `@vite("...")`. The key is `resources/js/app.tsx` for React and `resources/js/app.ts` for Vue and Svelte.

## Client entry

The optional `@inertiajs/vite` plugin resolves pages and mounts the app for you. With the plugin, the client entry file needs only this:

<Tabs>
  <Tab label="React">

```ts
import { createInertiaApp } from '@inertiajs/react'

createInertiaApp()
```

  </Tab>
  <Tab label="Vue">

```ts
import { createInertiaApp } from '@inertiajs/vue3'

createInertiaApp()
```

  </Tab>
  <Tab label="Svelte">

```ts
import { createInertiaApp } from '@inertiajs/svelte'

createInertiaApp()
```

  </Tab>
</Tabs>

Without the plugin, you provide the resolver and the setup function yourself.

<Tabs>
  <Tab label="React">

```tsx
// resources/js/app.tsx
import { createInertiaApp, type ResolvedComponent } from '@inertiajs/react'
import { createRoot } from 'react-dom/client'

createInertiaApp({
  resolve: (name) => {
    const pages = import.meta.glob<{ default: ResolvedComponent }>('./Pages/**/*.tsx', { eager: true })
    return pages[`./Pages/${name}.tsx`]
  },
  setup({ el, App, props }) {
    if (!el) throw new Error('Inertia root element not found')
    createRoot(el).render(<App {...props} />)
  },
})
```

  </Tab>
  <Tab label="Vue">

```ts
// resources/js/app.ts
import { createApp, h, type DefineComponent } from 'vue'
import { createInertiaApp } from '@inertiajs/vue3'

createInertiaApp({
  resolve: (name) => {
    const pages = import.meta.glob<{ default: DefineComponent }>('./Pages/**/*.vue', { eager: true })
    return pages[`./Pages/${name}.vue`]
  },
  setup({ el, App, props, plugin }) {
    if (!el) throw new Error('Inertia root element not found')
    createApp({ render: () => h(App, props) }).use(plugin).mount(el)
  },
})
```

  </Tab>
  <Tab label="Svelte">

```ts
// resources/js/app.ts
import { mount } from 'svelte'
import { createInertiaApp, type ResolvedComponent } from '@inertiajs/svelte'

createInertiaApp({
  resolve: (name) => {
    const pages = import.meta.glob<ResolvedComponent>('./Pages/**/*.svelte', { eager: true })
    return pages[`./Pages/${name}.svelte`]
  },
  setup({ el, App, props }) {
    if (!el) throw new Error('Inertia root element not found')
    mount(App, { target: el, props })
  },
})
```

  </Tab>
</Tabs>

## Pages

A page file receives the props from `Render(...)` as normal component props.

<Tabs>
  <Tab label="React">

```tsx
// resources/js/Pages/Users/Index.tsx
import { Link } from '@inertiajs/react'

export default function Index({ users }: { users: { id: number; name: string }[] }) {
  return (
    <ul>
      {users.map((u) => (
        <li key={u.id}><Link href={`/users/${u.id}`}>{u.name}</Link></li>
      ))}
    </ul>
  )
}
```

  </Tab>
  <Tab label="Vue">

```vue
<!-- resources/js/Pages/Users/Index.vue -->
<script setup lang="ts">
import { Link } from '@inertiajs/vue3'
defineProps<{ users: { id: number; name: string }[] }>()
</script>

<template>
  <ul><li v-for="u in users" :key="u.id"><Link :href="`/users/${u.id}`">{{ u.name }}</Link></li></ul>
</template>
```

  </Tab>
  <Tab label="Svelte">

```svelte
<!-- resources/js/Pages/Users/Index.svelte -->
<script lang="ts">
  import { Link } from '@inertiajs/svelte'
  let { users }: { users: { id: number; name: string }[] } = $props()
</script>

<ul>{#each users as u (u.id)}<li><Link href={`/users/${u.id}`}>{u.name}</Link></li>{/each}</ul>
```

  </Tab>
</Tabs>

## Development workflow

Run Vite in one terminal and the app in a second terminal:

```sh
npm run dev          # or bun/pnpm/yarn run dev; Vite writes wwwroot/hot
dotnet watch         # terminal 2: the app, ASPNETCORE_ENVIRONMENT=Development
```

Open the ASP.NET Core URL, not the Vite URL. Two servers run side by side:

| URL | What it is | Open it? |
|---|---|---|
| `http://localhost:5180` (the template's default) | Your app. ASP.NET Core routes the request, runs your endpoint and renders the Inertia page. | Yes |
| `http://localhost:5173` | The Vite dev server. It only serves JavaScript, CSS and hot-reload updates to the page above. | No. It has no pages, so it shows a blank page. |

Vite prints `localhost:5173` prominently when it starts. That address is for the browser's asset requests, not for you to open. In Development the app reads `wwwroot/hot` and renders the Vite tags. In production the app reads the manifest.

For production:

```sh
npm run build        # or bun/pnpm/yarn run build
dotnet publish -c Release
```

You need Node to build the assets. At runtime, you need Node only when server-side rendering (SSR) is enabled.

## Using @inertiajs/vite

The `@inertiajs/vite` plugin also provides the SSR dev endpoint and page resolution. In `vite.config.ts`, add it before the hot-file plugin:

<Tabs>
  <Tab label="React">

```ts
import react from '@vitejs/plugin-react'
import inertia from '@inertiajs/vite'

export default defineConfig({
  plugins: [
    react(),
    inertia({ ssr: { entry: 'resources/js/ssr.tsx', host: '127.0.0.1', port: 13714 } }),
    hotFile(),
  ],
})
```

  </Tab>
  <Tab label="Vue">

```ts
import vue from '@vitejs/plugin-vue'
import inertia from '@inertiajs/vite'

export default defineConfig({
  plugins: [
    vue(),
    inertia({ ssr: { entry: 'resources/js/ssr.ts', host: '127.0.0.1', port: 13714 } }),
    hotFile(),
  ],
})
```

  </Tab>
  <Tab label="Svelte">

```ts
import { svelte } from '@sveltejs/vite-plugin-svelte'
import inertia from '@inertiajs/vite'

export default defineConfig({
  plugins: [
    svelte(),
    inertia({ ssr: { entry: 'resources/js/ssr.ts', host: '127.0.0.1', port: 13714 } }),
    hotFile(),
  ],
})
```

  </Tab>
</Tabs>

Keep the SSR listener on the loopback address (`127.0.0.1`). The renderer trusts its output and has no authentication. The [SSR guide](/docs/server-side-rendering) covers the full setup.
