Inertia requests follow redirects with XHR, which is not always what the browser would do. Inertia.Net adjusts redirect responses so the client behaves correctly.

## Redirect helpers

```csharp
return Results.Redirect("/users");                 // standard redirect
return Back();                                     // Referer, else "~/" (app root, PathBase included)
return Back("/users");                             // Referer, else "/users"
return Location("https://billing.example.com");    // leave the SPA
```

`Back()` follows a `Referer` only when the `Referer` is an http(s) URL with the request's own host and port. When the `Referer` is unavailable, `Back()` tries the opt-in [previous URL](#previous-url) before the fallback. This prevents an open redirect. The scheme is not compared, so `Back()` works behind a TLS-terminating proxy. On HTTPS, an `http` Referer is upgraded to `https`.

## Previous URL

If a form returns `Back()` but the browser does not send its previous address (`Referer`), enable this option. For example, it helps when your site uses `Referrer-Policy: no-referrer`:

```csharp
builder.Services.AddInertia(o => o.State.RememberPreviousUrl = true);
```

After a successful page visit, a later `Back()` can use that saved address. `Back()` and the middleware's empty-response redirect look for a target in this order:

1. The same-host `Referer`.
2. The remembered URL.
3. The fallback.

`context.Inertia().PreviousUrl` reads the remembered URL. It returns `null` when the option is disabled, or when the remembered URL is absent or invalid. The remembered URL is user-controlled input, validated as a relative path.

Only successful status-200 page GET renders are remembered, including initial HTML visits. Partial reloads, prefetches, Precognition, non-GET requests and error pages are excluded. The value is the relative `PathBase + Path + QueryString`, without scheme or host. It is stored in the plain `.Inertia.Previous` session cookie. The cookie is `HttpOnly`, `SameSite=Lax`, `Path=/` and essential, and `Secure` follows `o.State.CookieSecurePolicy`. The cookie is written only when the URL changes. Set `o.State.PreviousUrlCookieName` to change the cookie name. The name must differ from `o.State.CookieName`.

The `.Inertia.Previous` cookie is used with both cookie and session state stores. It is **per browser, not per tab**: the most recent page render wins across tabs. The `Referer` still takes precedence when available.

## What the middleware changes

| Situation | Result |
|---|---|
| 302 for PUT, PATCH, DELETE or QUERY | Changed to **303 See Other**, so the browser follows with a GET |
| Redirect to another origin, non-prefetch | `409` with `X-Inertia-Location`: the client makes a full visit instead of an XHR the browser would block |
| Redirect whose `Location` contains `#`, non-prefetch | `409` with `X-Inertia-Redirect`: the client performs a full visit that keeps the fragment |
| `Location(url)` | `409` + `X-Inertia-Location` for Inertia requests, a plain `302` otherwise |
| Empty `200` response | Redirect back (302, or 303 for PUT/PATCH/DELETE/QUERY), using the same previous-URL and app-root fallback as `Back()` |
| `Vary` | `Vary: X-Inertia` is added to every response through the middleware |

Turn off external redirect conversion with `o.ConvertExternalRedirects = false` if the app intentionally redirects to another origin.

## Pages without a handler

```csharp
app.MapInertia("/about", "About", props);
```

`MapInertia` maps GET and HEAD to `Render("About", props)`, like Laravel's `Route::inertia`.

In MVC, `return this.InertiaView(props);` renders the action's own component. The default component name is `{Controller}/{Action}`. `AddInertiaMvc(o => o.ComponentResolver = ctx => ...)` changes the rule.

## History encryption

```csharp
builder.Services.AddInertia(o => o.EncryptHistory = true);   // every page

context.Inertia().EncryptHistory();                          // this response
context.Inertia().EncryptHistory(false);                     // opt out for this response
```

`encryptHistory` is written as `true` only when set and is not carried across redirects. The Inertia client encrypts its history state with the page's key.

## Clearing history

```csharp
app.MapPost("/logout", (HttpContext context) =>
{
    context.Inertia().ClearHistory();
    return Results.Redirect("/login");
});
```

`clearHistory` goes through the state store. It applies to the next page rendered after the redirect(s), and is then consumed. It is typically used before a redirect after logout.

## Preserving a fragment

```csharp
context.Inertia().PreserveFragment();
```

By default a redirect loses the URL fragment. `PreserveFragment()` keeps it across the next redirect. The client receives `preserveFragment: true` on the next page.

## Page URL

The page object's `url` is PathBase, Path and QueryString. If your app runs behind a proxy that rewrites paths, set `o.UrlResolver` to return the URL that the browser sees:

```csharp
o.UrlResolver = ctx => ctx.Request.GetEncodedUrl();
```

<Callout type="tip" title="History state is in the cookie">
Flash data, errors, `clearHistory` and `preserveFragment` share the state store. By default the state store is an encrypted cookie. See [Flash data](/docs/flash-data#where-state-is-kept).
</Callout>
