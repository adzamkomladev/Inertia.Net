Typed routes give every named endpoint a typed function in `routes.ts`, with typed parameters and request bodies. This page builds on [TypeScript types](/docs/typescript). The same `o.TypeScript` options write both files. Routes come from endpoint names, so they work the same whether an endpoint renders with `Render("Component", props)` or a [page record](/docs/page-records).

## Generate routes.ts

Set `RoutesOutputPath`, and every named endpoint gets a typed function in `routes.ts`. An endpoint gets its name from `WithName`, a controller route name, or a FastEndpoints `Description(x => x.WithName(...))`:

```csharp
o.TypeScript.RoutesOutputPath = "ClientApp/types/routes.ts";
app.MapGet("/users/{id:int}", ...).WithName("users.show");
app.MapPost("/users", (CreateUser input) => ...).WithName("users.store");
```

  <Tab label="React">

```tsx
import { Link, useForm } from '@inertiajs/react'
import { routes, type RouteBodies } from '../../types/routes'

export default function Create({ user }: { user: { id: number; name: string } }) {
  const form = useForm<RouteBodies['users.store']>({ name: '' })   // the request body, typed from CreateUser
  const posts = routes.users.show.url(user.id, { query: { tab: 'posts' } })   // '/users/1?tab=posts'

  return (
    <>
      {/* routes.users.show(1) is { url: '/users/1', method: 'get' } */}
      <Link href={routes.users.show(user.id)}>{user.name}</Link> <a href={posts}>Posts</a>
      <form onSubmit={(e) => { e.preventDefault(); form.submit(routes.users.store()) }}>
        <input value={form.data.name} onChange={(e) => form.setData('name', e.target.value)} />
        <button disabled={form.processing}>Create</button>
      </form>
    </>
  )
}
```

- Route parameters are typed from their constraints. Optional and catch-all parameters are optional.
- Every HTTP method of an endpoint has a variant (`routes.users.update.put(1)`).
- `routeConfig.base` prefixes every URL, for an app under a path base.
- `RouteBodies` holds the `[FromBody]` (or FastEndpoints request) type of each route that has one.
- Unnamed endpoints are skipped.

`o.TypeScript.LiveEvents(...)` also exports live event names and channels as `liveEvents`. See [Live props](/docs/live-props#reloading-scroll-and-merge-props).

To assert a route sent as a prop in tests, use `WhereRoute(key, url, method)`. See [Testing](/docs/testing).

## Generating at build time

Set `<InertiaGenerateTypesOnBuild>true</InertiaGenerateTypesOnBuild>` in the project file. Every build, including the one inside `dotnet publish`, then runs the app once with `--inertia-types` to write both files. The app starts without listening on any port and exits. If the write fails, the build fails. In CI, compare the result with the committed files:

```sh
dotnet build -p:InertiaGenerateTypesOnBuild=true
git diff --exit-code ClientApp/types
```

Component names are checked at compile time too. See [Page records](/docs/page-records#compile-time-component-checks).

## Instant visits

Named `MapInertia` routes expose their component to the generated GET function. For a regular handler with one known destination, declare its final client component explicitly:

```csharp
app.MapGet("/orders/{id:int}", (int id) => Render("Orders/Show", new { id }))
    .WithName("orders.show")
    .WithInertiaComponent("Orders/Show");
```

```tsx
<Link href={routes.orders.show(42)} instant>Order 42</Link>
```

The client shows the destination while the GET is pending. Let the page render a loading state until its page-specific data arrives. Use an ordinary link for conditional destinations. If a component transformer is configured, use explicit metadata only when you can declare the final name for that route.
