Precognition validates a form before the user submits it. The client sends the same POST as the form, with a `Precognition: true` header. The server validates the request and returns without running the handler. The [Minimal API React sample](https://github.com/adzamkomladev/Inertia.Net/tree/main/samples/MinimalApi.React) includes a login validation demo. The demo accepts dummy values and does not create an authentication session. A request and response look like this:

```http
POST /login HTTP/1.1
Precognition: true
Precognition-Validate-Only: email
Content-Type: application/json

{"email":"invalid","password":"password123"}

HTTP/1.1 422 Unprocessable Entity
Precognition: true
Vary: Precognition
Content-Type: application/json

{"message":"The Email field is not a valid e-mail address.","errors":{"email":["The Email field is not a valid e-mail address."]}}
```

The `message` is the first returned error. A valid request returns `204` and `Precognition-Success: true`. For Minimal APIs, register `AddValidation()` and map the endpoint like this:

```csharp
app.MapPost("/login", (LoginForm input) => Back().WithFlash("success", "Demo form submitted"))
   .WithInertiaPrecognition();
```

The sample's input model is:

```csharp
public sealed class LoginForm
{
    [Required, EmailAddress]
    public string? Email { get; set; }

    [Required, MinLength(8)]
    public string? Password { get; set; }
}
```

Import `System.ComponentModel.DataAnnotations`. `.WithInertiaPrecognition()` replaces `.WithInertiaValidation()`. Do not use both. `.WithInertiaPrecognition()` also handles normal validation redirects. Filters added after it do not run on precognitive requests. A precognitive request is a validation request that carries `Precognition: true`. FastEndpoints enables Precognition through `c.ConfigureInertia()`. MVC does not support Precognition.

## Client setup

Inertia 3 includes Precognition in its form integration. Each example validates on blur and displays the error:

`Precognition-Validate-Only` selects which errors the server returns, by field. Nested paths work too. A precognitive request still runs the validator, so keep database rules cheap. Validate on blur for login and payment forms. This avoids showing an error while the user is still typing. `setValidationTimeout(3000)` raises the debounce interval for expensive rules. It is not the HTTP deadline.

## Antiforgery and authorization

`UseInertiaAntiforgery()` validates precognitive POSTs like other unsafe requests. The Inertia client sends the token automatically. Authorization middleware runs before endpoint filters, so protected forms validate only for authorized users.

## Rate limiting

Precognitive POSTs pass through rate limiting before the endpoint filter. A single strict login bucket can therefore lock users out while they type. Use separate bounded partitions for validation and real submissions. To tell the two apart, check the endpoint's `InertiaPrecognitionMetadata` as well as `InertiaPrecognition.IsPrecognitive(request)`. The header alone does not guarantee that the handler is skipped. Do not use `GetNoLimiter` for validation, because validators consume CPU and may query a database. When the metadata is present the handler is skipped, so the validation bucket does not allow credential attempts.

When the rate limiter rejects a precognitive request, set `Precognition: true` on the 429 response. The header lets the client recognize the response. The validation request still rejects, so provide a retry or error message. Run `UseRouting`, `UseRateLimiter`, `UseInertia` and `UseInertiaAntiforgery` in that order. The example below shows a complete policy.

The following `AddServices` method is copied from the Minimal API sample's `LoginDemo` class. The sample's `_generation` field exists only to reset E2E test buckets. Real apps can partition on a stable client identity that suits their deployment. Import `System.Globalization`, `System.Threading.RateLimiting` and `Microsoft.AspNetCore.RateLimiting`. Declare `private static int _generation;` and `private static int _submissions;` in the `LoginDemo` class. The [complete sample class](https://github.com/adzamkomladev/Inertia.Net/blob/main/samples/MinimalApi.React/LoginDemo.cs) includes `LoginForm`, `LoginPage`, and the reset helper:

```csharp
    public static void AddServices(IServiceCollection services)
    {
        services.AddRateLimiter(options =>
        {
            options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;
            options.AddPolicy("login", http =>
            {
                var validation = http.GetEndpoint()?.Metadata.GetMetadata<InertiaPrecognitionMetadata>() is not null
                    && InertiaPrecognition.IsPrecognitive(http.Request);
                var client = http.Connection.RemoteIpAddress?.ToString() ?? "unknown";
                // The generation lets the sample's E2E reset endpoint give each test fresh buckets.
                var generation = Volatile.Read(ref _generation);
                if (validation)
                {
                    return RateLimitPartition.GetSlidingWindowLimiter($"validation:{client}:{generation}", _ => new SlidingWindowRateLimiterOptions
                    {
                        PermitLimit = 30,
                        Window = TimeSpan.FromMinutes(1),
                        SegmentsPerWindow = 6,
                        QueueLimit = 0,
                    });
                }

                return RateLimitPartition.GetFixedWindowLimiter($"submit:{client}:{generation}", _ => new FixedWindowRateLimiterOptions
                {
                    PermitLimit = 5,
                    Window = TimeSpan.FromMinutes(1),
                    QueueLimit = 0,
                });
            });
            options.OnRejected = (context, _) =>
            {
                var http = context.HttpContext;
                if (http.GetEndpoint()?.Metadata.GetMetadata<InertiaPrecognitionMetadata>() is not null
                    && InertiaPrecognition.IsPrecognitive(http.Request))
                {
                    http.Response.Headers[InertiaPrecognition.Header] = "true";
                    http.Response.Headers.Append("Vary", InertiaPrecognition.Header);
                }

                if (context.Lease.TryGetMetadata(MetadataName.RetryAfter, out var retryAfter))
                    http.Response.Headers.RetryAfter = Math.Ceiling(retryAfter.TotalSeconds).ToString(CultureInfo.InvariantCulture);
                return ValueTask.CompletedTask;
            };
        });
    }
```

Call `AddServices` before you build the app. The sample also adds 429 to error-page handling for real Inertia submissions, because 429 is not a default error-page status:

```csharp
builder.Services.AddInertiaErrorPages(o => o.StatusCodes.Add(429));
```

Map an error page with a retry message. Precognitive requests that accept JSON keep their 429 response and `Precognition: true` header. Attach the policy to the endpoint:

```csharp
LoginDemo.AddServices(builder.Services);
// After builder.Build():
app.UseInertiaErrorPages(); // wraps rate-limit and page responses
app.UseRouting();
app.UseRateLimiter();
app.UseInertia();
app.UseInertiaAntiforgery(); // after UseAuthentication() in an app with sign-in
LoginDemo.MapRoutes(app);
```

The sample routes use this method:

```csharp
    public static void MapRoutes(WebApplication app)
    {
        app.MapGet("/login", () => Render("Login", new LoginPage(Volatile.Read(ref _submissions))));
        app.MapPost("/login", (LoginForm input) =>
        {
            Interlocked.Increment(ref _submissions);
            return Back().WithFlash("success", "Demo form submitted");
        }).WithInertiaPrecognition().RequireRateLimiting("login");
    }
```

The sample partitions by remote IP for demonstration. When your app runs behind a proxy, configure trusted forwarded headers. Choose a partition key that suits your authentication and abuse model.

## Testing

Use an `Inertia.Net.Testing` client that keeps cookies. Load the form page and attach its XSRF token to each request. This test covers an endpoint that validates `email`:

```csharp
client.DefaultRequestHeaders.Accept.ParseAdd("text/html");
using var page = await client.GetAsync("/login");
async Task<HttpResponseMessage> ValidateAsync(string email)
{
    using var request = new HttpRequestMessage(HttpMethod.Post, "/login")
    {
        Content = JsonContent.Create(new { email, password = "password123" }),
    };
    request.WithXsrfToken(page);
    request.Headers.Add(InertiaPrecognition.Header, "true");
    request.Headers.Add(InertiaPrecognition.ValidateOnlyHeader, "email");
    return await client.SendAsync(request);
}
using var valid = await ValidateAsync("ann@example.com");
Assert.Equal(HttpStatusCode.NoContent, valid.StatusCode);
Assert.Equal("true", valid.Headers.GetValues(InertiaPrecognition.SuccessHeader).Single());
using var invalid = await ValidateAsync("invalid");
Assert.Equal(HttpStatusCode.UnprocessableEntity, invalid.StatusCode);
using var body = JsonDocument.Parse(await invalid.Content.ReadAsStringAsync());
Assert.True(body.RootElement.GetProperty("errors").TryGetProperty("email", out _));
```

Import `System.Net`, `System.Net.Http.Json`, `System.Text.Json`, `Inertia.Net` and `Inertia.Net.Testing`. [Testing](/docs/testing#testing-a-form-with-antiforgery) shows the client and token setup.

## Protocol reference

| Header | Direction | Meaning |
|---|---|---|
| `Precognition: true` | Request and response | Identifies a validation request and response |
| `Precognition-Validate-Only` | Request | Comma-separated client field paths whose errors are returned |
| `Precognition-Success: true` | Response | Validation succeeded (204) |
| `Vary: Precognition` | Response | Varies the response by request type |

A validation failure returns `422`. A rate limiter may return `429`. `InertiaPrecognition.IsPrecognitive(HttpRequest)` checks the header. `InertiaPrecognitionMetadata` identifies endpoints whose handler is skipped for precognitive requests.
