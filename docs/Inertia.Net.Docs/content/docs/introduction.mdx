Inertia.Net lets your C# routes render React, Vue or Svelte pages. In each route, you choose a component and pass it the data it needs. Inertia calls that data **props**. Sign-in, validation and database queries live in your ASP.NET Core app. Your frontend framework handles what the user sees and interacts with.

You can build and ship the server and frontend as one app. Start with a working todo app and try a C# validation rule in the browser. [First 10 minutes](/docs/first-10-minutes)

## How it works

<Steps>
  <Step title="An endpoint chooses a page and its props">

```csharp
app.MapGet("/", () => Render("Home", new InertiaProps
{
    ["greeting"] = "Hello from .NET",
}));
```

  </Step>
  <Step title="Inertia connects it to a client component">

<Tabs>
  <Tab label="React">

```tsx
export default function Home({ greeting }: { greeting: string }) {
  return <h1>{greeting}</h1>
}
```

  </Tab>
  <Tab label="Vue">

```vue
<script setup lang="ts">
defineProps<{ greeting: string }>()
</script>

<template>
  <h1>{{ greeting }}</h1>
</template>
```

  </Tab>
  <Tab label="Svelte">

```svelte
<script lang="ts">
  let { greeting }: { greeting: string } = $props()
</script>

<h1>{greeting}</h1>
```

  </Tab>
</Tabs>

  </Step>
  <Step title="The client updates the page">
    The first request returns HTML with the page object embedded. The page object holds the component name and its props. Inertia links and form submissions request the next page in the background and swap the component while the browser keeps its state.
  </Step>
</Steps>

Your .NET app still handles the request. The adapter adds the protocol middleware, prop resolution, redirect semantics, flash data and asset tags.

## Feature matrix

| | Minimal API | MVC controllers | FastEndpoints |
|---|:---:|:---:|:---:|
| Package | `Inertia.Net` | `Inertia.Net` + `Inertia.Net.Mvc` | `Inertia.Net` + `Inertia.Net.FastEndpoints` |
| Render / Back / Location | `Render(...)` returns `IResult` | same, return `IResult` from an action | `Send.InertiaAsync(...)` or return the result |
| Validation redirect with errors | `.WithInertiaValidation()` | `ModelState` filter (global) | `c.ConfigureInertia()` pre-processor |
| Precognition | `.WithInertiaPrecognition()` | not available | `c.ConfigureInertia()` |
| Razor root view | no (`app.html` template) | optional (tag helpers) | no (`app.html` template) |
| Native AOT | yes | no (MVC itself is not AOT) | yes (with the FastEndpoints source generator) |

The client packages are `@inertiajs/react`, `@inertiajs/vue3` and `@inertiajs/svelte`, all version 3. Inertia.Net does not support v2 clients.

## This documentation site

This site is an Inertia.Net app. The sidebar, search, docs pages and theme switcher are React components rendered by an ASP.NET Core Minimal API. Navigation uses Inertia links. The source is in `docs/Inertia.Net.Docs`, so the site is also a real example.

## Requirements

- .NET 10 or .NET 11 SDK
- JavaScript frontend build tools with npm, Bun, pnpm or Yarn. Managed SSR requires Node.js or Bun at runtime
- An Inertia.js v3 client package for React, Vue or Svelte

<Callout type="tip" title="Starting from scratch?">
Use the starter template: `dotnet new install Inertia.Net.Templates`, then `dotnet new inertia -n MyApp --framework react`. It includes working pages, a form with validation, flash messages, CSRF and Vite configuration.
</Callout>
