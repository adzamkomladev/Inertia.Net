Inertia.Net is split into small packages. Install the core package and one optional backend integration.

Every package is on [NuGet](https://www.nuget.org/profiles/adzamkomladev); the names below link to their NuGet pages.

| Package | Install when |
|---|---|
| [`Inertia.Net`](https://www.nuget.org/packages/Inertia.Net) | always. The core adapter, Minimal API support, Vite, server-side rendering (SSR), state store and antiforgery |
| [`Inertia.Net.Mvc`](https://www.nuget.org/packages/Inertia.Net.Mvc) | you use MVC controllers: `ModelState` filter, Razor root view and tag helpers |
| [`Inertia.Net.FastEndpoints`](https://www.nuget.org/packages/Inertia.Net.FastEndpoints) | you use FastEndpoints: `Send` extensions, validation pre-processor and Precognition |
| [`Inertia.Net.Live.SignalR`](https://www.nuget.org/packages/Inertia.Net.Live.SignalR) | you deliver [live props](/docs/live-props) over SignalR: hub, channel authorization and local transport |
| [`Inertia.Net.Live.Sse`](https://www.nuget.org/packages/Inertia.Net.Live.Sse) | you deliver [live props](/docs/live-props#server-sent-events) over Server-Sent Events, with no client library |
| [`Inertia.Net.Redis`](https://www.nuget.org/packages/Inertia.Net.Redis) | you share [cached props](/docs/props#cached-props) and SSR renders, or carry [live props across instances](/docs/live-props-at-scale), through Redis |
| [`Inertia.Net.Postgres`](https://www.nuget.org/packages/Inertia.Net.Postgres) | you carry [live props across instances](/docs/live-props-at-scale) and workers over PostgreSQL `LISTEN`/`NOTIFY`, with publish on commit |
| [`Inertia.Net.EntityFrameworkCore`](https://www.nuget.org/packages/Inertia.Net.EntityFrameworkCore) | you page EF Core queries with numbered or cursor pagination |
| [`Inertia.Net.MongoDB`](https://www.nuget.org/packages/Inertia.Net.MongoDB) | you page MongoDB finds with numbered or cursor [pagination](/docs/pagination#with-mongodb) |
| [`Inertia.Net.Testing`](https://www.nuget.org/packages/Inertia.Net.Testing) | in your test project: fluent assertions over Inertia responses, and `FakeBackplane` for multi-instance live tests |
| [`Inertia.Net.Templates`](https://www.nuget.org/packages/Inertia.Net.Templates) | you want to start from a complete app. Install it with `dotnet new install Inertia.Net.Templates`. It also adds pages with `dotnet new inertia-page` |

```sh
dotnet add package Inertia.Net --version 1.10.0
dotnet add package Inertia.Net.Mvc --version 1.10.0            # MVC only
dotnet add package Inertia.Net.FastEndpoints --version 1.10.0  # FastEndpoints only
dotnet add package Inertia.Net.EntityFrameworkCore --version 1.10.0 # EF Core pagination
dotnet add package Inertia.Net.Testing --version 1.10.0        # test projects
dotnet add package Inertia.Net.Live.SignalR --version 1.10.0   # live props over SignalR
dotnet add package Inertia.Net.Live.Sse --version 1.10.0        # live props over Server-Sent Events
dotnet add package Inertia.Net.Redis --version 1.10.0          # Redis cache store and live backplane
dotnet add package Inertia.Net.Postgres --version 1.10.0       # PostgreSQL live backplane
dotnet add package Inertia.Net.MongoDB --version 1.10.0        # MongoDB pagination
```

Use the same version for every Inertia.Net package. The package version and the Inertia.js protocol version are separate numbers: Inertia.Net 1.10.0 implements Inertia.js v3.

## Requirements

- .NET 10 or .NET 11 SDK and a `Microsoft.NET.Sdk.Web` project.
- JavaScript frontend build tools with npm, Bun, pnpm or Yarn. Managed SSR requires Node.js or Bun at runtime.
- An Inertia.js v3 client: `@inertiajs/react`, `@inertiajs/vue3` or `@inertiajs/svelte`.

## .NET 10 and .NET 11

Every package ships `net10.0` and `net11.0` assemblies. NuGet picks the one that matches your app. On .NET 11, keep these points in mind:

- **Use 1.8.0 or later on .NET 11.** Inertia.Net 1.7.1 and earlier were built against .NET 10 only. .NET 11 changed the experimental resolver API of `Microsoft.Extensions.Validation`. Because of that change, `WithInertiaValidation()` and `WithInertiaPrecognition()` from 1.7.1 fail on .NET 11 with `TypeLoadException: Could not load type 'Microsoft.Extensions.Validation.IValidatableInfo'`.
- **Retarget, don't roll forward.** A `net10.0` app that calls `AddValidation()` fails when it runs on the .NET 11 runtime (`DOTNET_ROLL_FORWARD=LatestMajor`). It fails whatever adapter it uses, because the validation source generator wrote .NET 10 types that .NET 11 removed. To fix it, set `<TargetFramework>net11.0</TargetFramework>` and rebuild.
- **Dependencies follow the target framework.** On `net11.0`, `Inertia.Net.EntityFrameworkCore` depends on EF Core 11 and `Inertia.Net.FastEndpoints` depends on FastEndpoints 9. On `net10.0` they use EF Core 10.0.15 and FastEndpoints 8.3.0. Reference the `FastEndpoints.Generator` version that matches your FastEndpoints version.
- **Async validators.** Errors from `AsyncValidationAttribute` and `IAsyncValidatableObject` go through `WithInertiaValidation()` and `WithInertiaPrecognition()` in the same way as synchronous errors. See [Validation and errors](/docs/validation-and-errors).
- **Automatic CSRF check.** Apps built with `WebApplication.CreateBuilder` also get the framework's `Sec-Fetch-Site`/`Origin` check. `UseInertiaAntiforgery()` is still the token check Inertia needs. See [CSRF and antiforgery](/docs/csrf-and-antiforgery).
- **C# 15 unions** work as props and in the generated TypeScript. See [Props](/docs/props) and [TypeScript](/docs/typescript).
- **Compression.** `AddResponseCompression()` also offers Zstandard and always adds `Vary: Accept-Encoding`. Inertia's `Vary: X-Inertia` stays next to it.

## Start from the template

```sh
dotnet new install Inertia.Net.Templates@1.10.0
dotnet new inertia -n MyApp --framework react
cd MyApp
```

For another client, choose `--framework vue` or `--framework svelte`. For cookie sign-in, add `--auth` (see [Authentication](/docs/authentication)). The template includes working pages, a Todos form, validation, flash messages, CSRF protection and Vite configuration. The template's client has `lint` (oxlint), `format` and `format:check` (oxfmt) scripts. The `build` script type-checks first. Outside Development the app redirects to HTTPS and sends HSTS. The app targets .NET 10 (LTS) by default. To target .NET 11, add `--tfm net11.0`.

Install dependencies with the package manager you chose for your app. All four are supported:

| Package manager | Install dependencies | Start Vite | Build assets |
|---|---|---|---|
| npm | `npm install` | `npm run dev` | `npm run build` |
| Bun | `bun install` | `bun run dev` | `bun run build` |
| pnpm | `pnpm install` | `pnpm run dev` | `pnpm run build` |
| Yarn | `yarn install` | `yarn run dev` | `yarn run build` |

Then run `dotnet watch`. The template sets `o.Vite.StartDevServer = true`, so in Development the app starts Vite with the package
manager whose lock file is in the project, and stops it when the app stops. To run Vite in a terminal of its own, start it there
first (the app then leaves it alone), or remove that line. For production, run the build command from your row of the table, then
run `dotnet publish -c Release`. Keep the lockfile for the package manager you choose.

### Add a page

The template package also has an item template that writes a page record and the matching page file. Run it in the project
directory after the project has been restored once, because it reads the root namespace from the project:

```sh
dotnet new inertia-page --component Users/Index                      # React: ClientApp/pages/Users/Index.tsx
dotnet new inertia-page --component Reports --framework vue          # or svelte
```

`--component Users/Index` writes `UsersIndexPage.cs`, a `UsersIndexPage(string Message)` record with `Component => "Users/Index"`. It
also writes `ClientApp/pages/Users/Index.tsx`, typed with `InertiaPages['Users/Index']`. Register the record in your JSON context by adding `[JsonSerializable(typeof(UsersIndexPage))]` to `AppJsonContext` in `Program.cs`
(the command reminds you), then render it with `Render(new UsersIndexPage("Hello"))`. The page type appears in `ClientApp/types/inertia.d.ts` the next time the app starts in
Development, or after `npm run types`.

## Namespace and global usings

The namespace is `Inertia.Net` and the static factory class is `Inertia.Net.Inertia`. C# resolves a leading `Inertia` to the namespace, so `Inertia.Render(...)` does not compile outside the `Inertia.Net` namespace.

The package's `buildTransitive` props file adds both global usings below when `<ImplicitUsings>enable</ImplicitUsings>` is set. That setting is the default in new projects.

```csharp
global using Inertia.Net;
global using static Inertia.Net.Inertia;
```

With these usings, you write `Render(...)`, `Defer(...)`, `Once(...)`, `Back()` and `Location(...)` without a namespace or class prefix.

<Callout type="warning" title="Opting out">
Set `<InertiaNetImplicitUsings>false</InertiaNetImplicitUsings>` and add `using static Inertia.Net.Inertia;` yourself, or call `Inertia.Net.Inertia.Render(...)`. `HttpContext.Inertia()` is an extension method and works as written.
</Callout>
