Behind a load balancer or reverse proxy that terminates TLS, Kestrel sees plain HTTP unless the scheme is forwarded. When the scheme is not forwarded, the state and `XSRF-TOKEN` cookies are not marked `Secure`.

## Forwarded headers

```csharp
builder.Services.Configure<ForwardedHeadersOptions>(o =>
{
    o.ForwardedHeaders = ForwardedHeaders.XForwardedFor | ForwardedHeaders.XForwardedProto;
    // o.KnownProxies / o.KnownNetworks: list your proxy, or headers from anyone else are ignored
});

app.UseForwardedHeaders();               // first
app.UseInertia();
```

When the scheme cannot be forwarded, force the cookies to be secure:

```csharp
builder.Services.AddInertia(o => o.State.CookieSecurePolicy = CookieSecurePolicy.Always);
app.UseInertiaAntiforgery(o => o.SecurePolicy = CookieSecurePolicy.Always);
```

## Multi-instance state

When the app runs on several instances, share the Data Protection key ring, so that every instance can read the state cookie and antiforgery tokens:

```csharp
builder.Services.AddDataProtection()
    .PersistKeysToFileSystem(new DirectoryInfo("/var/keys"))
    .SetApplicationName("MyApp");
```

If you use the session store, sessions must be shared too, for example with Redis. The default cookie store only needs shared Data Protection keys.

Keep the SSR server on loopback on each instance. See [Server-side rendering](/docs/server-side-rendering).

## Compression

Page JSON and HTML compress five to ten times. Compress at the proxy, or in the app:

```csharp
builder.Services.AddResponseCompression();   // Brotli and gzip; Zstandard too on .NET 11 (which always adds Vary: Accept-Encoding)
app.UseResponseCompression();                // before UseStaticFiles and UseInertia
```

Over HTTPS, the middleware compresses only when you set `o.EnableForHttps = true`. Review BREACH for your pages first. Inertia.Net keeps the antiforgery token in a cookie, not in the body. However, a page that reflects request input next to a secret is still exposed.

## Asset caching

Vite puts a content hash in every built file name, so files under `build/assets` can be cached as immutable:

```csharp
app.UseStaticFiles(new StaticFileOptions
{
    OnPrepareResponse = c =>
    {
        if (c.Context.Request.Path.StartsWithSegments("/build/assets"))
        {
            c.Context.Response.Headers.CacheControl = "public, max-age=31536000, immutable";
        }
    },
});
```

`app.MapStaticAssets()` does the same with build-time Brotli. Use it when the client is built before `dotnet publish`, so that the files are in `wwwroot` when the static web assets manifest is generated.

## Path base

Call `app.UsePathBase("/app")` before `UseInertia()`. The page `url`, Vite URLs and `Back()` include the path base. If a proxy rewrites paths, set `o.UrlResolver` to return the URL that the browser sees.

## Health and readiness

```csharp
builder.Services.AddHealthChecks().AddInertiaSsr();
app.MapHealthChecks("/health");
```

The SSR health check is covered in [Server-side rendering](/docs/server-side-rendering#7-health-check).

## Deployment checklist

- [ ] The client `build` script runs before `dotnet publish` (`npm run build`, `bun run build`, `pnpm run build` or `yarn run build`), or `wwwroot/build` is copied into the publish output.
- [ ] `app.html` is copied to the publish output.
- [ ] Forwarded headers are configured, or cookies are forced secure.
- [ ] Data Protection keys are shared between instances.
- [ ] Static assets under `/build/assets` are cached as immutable.
- [ ] Response compression is enabled at the proxy or in the app.
- [ ] SSR listens on loopback and its bundle is deployed when SSR is enabled.
- [ ] The client build and server build are the same version, so `X-Inertia-Version` converges.

## Hosts and SSR failures

Keep `AllowedHosts` configured. `Ssr.ConnectTimeout` limits the time to establish a connection. The default is five seconds. In `SsrMode.Required`, the exception message is generic. Diagnostic properties may contain private renderer details and should stay in trusted logs.

## Check published frontend assets

Add a readiness check for the Vite entry keys used by your root view. Register it for production after building the frontend.

```csharp
builder.Services.AddHealthChecks()
    .AddInertiaVite(["ClientApp/app.tsx"], tags: ["ready"]);

// After building the app:
app.MapHealthChecks("/health/ready", new Microsoft.AspNetCore.Diagnostics.HealthChecks.HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("ready"),
});
```

The first probe checks the local build directory for the entry and the files reachable through both static and dynamic imports. An unhealthy result identifies a missing manifest key or file. The result is kept for the lifetime of the host, so publish assets before starting it and restart after replacing them. Use `mount: "admin"` to check a named mount. For CDN deployments, run the check on the staged local files before uploading them.
