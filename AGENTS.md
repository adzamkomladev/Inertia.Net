# Repository instructions

These rules apply to Codex, Claude, and any other coding assistant working in this repository.

## No assistant attribution

- Never attribute repository work to yourself, another assistant, an AI model, or its provider.
- Do not add AI author/co-author trailers, signatures, badges, session links, or "generated by/with" credits to commits, pull requests, issues, code comments, documentation, changelogs, or release notes.
- Use the repository's existing Git identity. Do not replace it with an assistant identity or invent a human author.
- Before submitting a commit or pull request, inspect the complete message/body and remove any assistant attribution you introduced.
- Preserve existing human authorship and third-party license notices. Do not rewrite existing Git history unless explicitly requested.

## Project

- .NET 10 Inertia v3 adapter. SDK selection is in `global.json`; package versions are centralized in `Directory.Packages.props`.
- `src/Inertia.Net` contains the protocol, props, state, Vite, and SSR implementation. MVC, FastEndpoints, and testing helpers are separate packages under `src/`.
- Read `docs/protocol.md` before protocol changes, including its deliberate deviations. Public usage is documented in `README.md` and package READMEs.
- Keep changes small, reuse existing helpers, and trace callers before changing shared behavior. Preserve Native AOT support and source-generated System.Text.Json metadata.
- Follow `.editorconfig`; keep nullable annotations and public XML documentation. Add regression coverage to the existing test projects for behavior changes.

## Verification

Run from the repository root:

```sh
dotnet build Inertia.Net.slnx -c Release -warnaserror
dotnet test --solution Inertia.Net.slnx -c Release --no-build
```

- Protocol conformance tests cover Minimal API, MVC, and FastEndpoints. Node must be available for managed SSR tests.
- For packaging changes: `dotnet pack Inertia.Net.slnx -c Release --no-build -warnaserror -o artifacts`.
- For AOT changes: `bash eng/aot-smoke.sh` on Linux with clang and zlib installed.
- For sample/client changes: use the sample build and Playwright commands in `.github/workflows/ci.yml` and `samples/README.md`.
- Report checks actually run and any limitations; never claim unrun checks passed.
